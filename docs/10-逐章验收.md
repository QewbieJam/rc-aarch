# ✅ 逐章验收（真机树莓派 · ch1 → ch9）

一条命令，在**真实树莓派 4B / openEuler MCS / Jailhouse cell3** 上按章节顺序跑验收，
打印 PASS/FAIL 表和对应证据。

```sh
./scripts/verify-chapters.sh                 # 默认 BOARD=root@192.168.31.75
BOARD=root@192.168.31.78 ./scripts/verify-chapters.sh
WITH_SHELL=0 ./scripts/verify-chapters.sh    # 跳过 ch7+ 的 ivshmem 控制台
LOG=/tmp/verify.log ./scripts/verify-chapters.sh
```

脚本做三件事：

1. 编译内核；编译 root 侧 `ivshm-console`（ch7+ 用）；
2. 确保 `jailhouse enable`、把 ivshmem 从 `ivshmem-net` 切到 `uio`，起守护进程并喂一段
   shell 命令（`help` / `cmdline_args a b` / `cat_filea` / `exit`）；
3. `RELOAD=1` 部署 cell3，抓完整控制台日志，逐章断言后打印报表。

> 产物：`verify-chapters.log`（cell3 控制台）、`verify-shell.log`（root 侧守护进程看到的
> guest 输出）。失败时先看这两份日志。

## 实现说明（为什么这么测）

- **一次部署覆盖全部章节**：`initproc` 的 app 列表按章节顺序排好了
  （`00hello_world` → `conc_test` → `03sbrk` → `filetest_simple` → … → `fs_perf` → `user_shell`），
  所以一次上板就能拿到所有证据；失败时按章节名即可定位到 app。
- **ch3 的交错**：`02busy` 不主动 yield，靠 10ms 时间片被抢占；脚本只要求 A/B 序列里
  出现交替（`AB`/`BA` 都算），不强制严格 A0/B0/A1 的顺序（调度时序有随机性）。
- **ch7+ 单独起守护进程**：root 侧守护进程必须**先于** cell 启动（要初始化自己的共享段），
  所以脚本先起守护进程再部署；守护进程等到 guest 的新 `gen` 才发命令。
- **ch1 验的是机制**：ch1 当时的行"Hello, world!"已经演化成现在的完整内核；这里验证的是
  它建立的那套地基（0xFA000000 入口、UART、clear_bss、恒等映射）仍然成立。

## 这套验收抓到过的问题

- **ch4 首跑 FAIL**：`03sbrk` 的 `sbrk(0)` 返回 `0xffffffffffffffff`。
  根因是 ch7 引入 argv 后，`exec` 把 `heap_bottom` 设成了"压完 argv 的 sp"，
  而 `from_elf` 建的堆区起点是"压 argv 之前的栈顶"——`append_to` 找不到对应 MapArea，
  sbrk 全部失败。修法：`exec` 里单独记 `heap_base` 给 `heap_bottom/program_brk`，
  `user_sp` 仍用压完 argv 的值。这个 bug 在 ch7/ch8 的 app 列表里没被覆盖到，
  是逐章验收把它翻出来的。
