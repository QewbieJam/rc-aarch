## 三、这一阶段踩到/修掉的关键 bug

| # | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | exec 到同 VA 的不同 app 偶发取到旧指令 | ARMv8 改地址空间后 I-cache 必须失效 | `MemorySet::activate` 里加 `ic iallu` |
| 2 | pipe_large 数据整片错、父子校验和相同（假通过）| AArch64 EL0/EL1 共用 SIMD/FP 寄存器，内核 memcpy 把用户 v0 写坏 | TrapContext 存 q0~q31/FPCR/FPSR |
| 3 | 共享内存写好但 root 读到旧/错位 | "read 下标"写进了对方只读段；且未按代（gen）识别重新初始化 | read 写自己段、free 读对方段；加 gen + 启动丢弃旧数据 |
| 4 | 任务一跑起来，中断里访问共享内存就缺页 | 用户页表只共享内核 L1[3]，共享内存在 L1[1] | 用户页表额外挂 L1[1] |
| 5 | ch8 启动即 panic"进程已经回收了" | PCB 强引用在 `new()` 返回时归零（TCB 只有 Weak）| `new`/`fork` 返回前 `register_process` |
| 6 | 信号量"还没 up 就被放行" | `suspend` 是 yield，会把等待者放回就绪队列 | 新增 `block_current_and_run_next`（真 sleep）|
| 7 | 3 个线程拿到同一个 tid | `pid_alloc().0` 的句柄被临时 Drop，tid 立刻被复用 | TCB 持有 `tid_handle` |
| 8 | `sbrk(0)` 返回 -1（逐章验收抓到）| ch7 的 argv 压栈把 heap_bottom 挪离了堆区起点 | exec 里单独记 `heap_base` 给 heap_bottom/program_brk |

## 四、分支结构（为什么平台上没有 ch8/ch9 这两个分支）

之前每一章都是**单独拉分支**（`ch1`…`ch7`）；从 ch7 收尾之后改了做法：

```
ch7        冻结（管道/信号/argv + SIMD 修复）
 └─ ch7+   演进主线：可回收堆 → ivshmem 控制台 → ch8 线程/同步 → ch9 块缓存 → 逐章验收
      ├─ ch8   快照：414ea9e（ch8 完成点）
      └─ ch9   快照：最新（含 ch9 与验收脚本）
```

也就是说 **ch8、ch9 的内容一直在 `ch7+` 里**，只是没有单独建分支，所以平台上看起来"只有 ch1~ch7 和 ch7+"。现在补上了 `ch8` / `ch9` 两个快照分支，方便按章节查看。
