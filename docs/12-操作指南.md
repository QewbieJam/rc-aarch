# rc-aarch 操作指南（root cell → 非根 cell → ivshmem-net）

> 面向“我想用它做点什么”的实操手册：每一层能做什么、怎么做、有什么限制。
> 板子：树莓派 4B ｜ root cell：openEuler Embedded Linux ｜ 非根 cell：rc-aarch（我们的 Rust OS）

```
宿主机 Debian（构建/部署/验收）
   │ ssh / scp
   ▼
root cell（openEuler Linux，CPU 0–2）—— 管网络、串口、SD 卡、Jailhouse
   │ Jailhouse 命令 / /dev/jailhouse / /dev/uio0
   ▼
非根 cell rc-aarch（我们的 OS，CPU 3，内存 0xFA000000 起）
   │ 共享内存：0x6FFFE000（状态表）+ 0x6FFFF000 / 0x7007E000（两段输出）
   ▼
你的终端（ssh → root cell → ivshm-console → 虚拟机里的 shell）
```

---

## 一、各层能用的功能

### 1. 宿主机（Debian，`~/rc-aarch`）

| 能做什么 | 命令 / 文件 |
|---|---|
| 编译内核（会顺带编译 user 下所有 app）| `cd os-cell3 && RUSTUP_TOOLCHAIN=stable cargo build --release` |
| 编译 cell 配置 | `./scripts/build-cell.sh` |
| 编译共享内存守护进程 | `aarch64-linux-gnu-gcc -O2 -static -o /tmp/ivshm-console tools/ivshm-console.c` |
| 部署/重启 cell（RELOAD：不 destroy）| `RELOAD=1 ROOTCELL=root@192.168.31.75 SSHOPTS="-F /dev/null -o StrictHostKeyChecking=accept-new" ./scripts/deploy-cell3.sh` |
| 全套逐章验收（宿主机驱动）| `./scripts/verify-chapters.sh` |
| 打包上传（给板端验收用）| `./scripts/pack-verify.sh` |
| 按 MAC 找板子（现在需显式给 MAC）| `MAC=dc:a6:32:cc:41:b4 ./scripts/find-board.sh` |
| 生成 PPT / Word | `docs/ppt/make_ppt.py`、`docs/doc/make_docx.py` |

### 2. root cell（Linux 侧，ssh 进去）

```sh
ssh root@192.168.31.75        # 密码 openEuler@2021（仅首次/密钥丢失时）
```

| 能做什么 | 命令 / 位置 |
|---|---|
| 看 Jailhouse 是否使能 | `cat /sys/devices/jailhouse/enabled` |
| 使能/关闭 | `jailhouse enable /usr/share/jailhouse/cells/rpi4.cell` / `jailhouse disable` |
| 管理 cell | `jailhouse cell list`、`create /root/rc-aarch.cell`、`load --name rc-aarch /root/rc-aarch.elf`、`start --name rc-aarch`、`shutdown --name rc-aarch` |
| 读虚拟机控制台（增量）| `exec 3</dev/jailhouse; dd bs=8192 count=1 iflag=nonblock <&3` |
| 读控制台快照（仅前 2KB）| `cat /sys/devices/jailhouse/console` |
| 共享内存访问（uio 模式）| `/dev/uio0` 的 map0~map3（见第四节）|
| 与虚拟机通信 | `/root/ivshm-console`（`-i` 交互、`-s 文本`、`-n 轮次`、`-r 重置`）|
| 看驱动日志 | `dmesg | grep -i ivshmem` |
| ivshmem 网络（net 模式）| `ip -o addr show ivshm0`（10.0.0.1/24）|
| 切驱动 | `scripts/setup-ivshm-uio.sh`（net→uio）；切回见第五节 |

> ⚠️ root cell 的根文件系统在内存里（initramfs）：`/root`、`/tmp` 里的东西**重启即丢**；
> 每次重启后要重新 `jailhouse enable`、重新上传文件、重新放 SSH 公钥。

### 3. 非根 cell（rc-aarch，我们的 OS 里）

进入方式：root cell 上跑 `/root/ivshm-console -i -d 600`，然后在里面敲命令。

| 能做什么 | 命令 / 说明 |
|---|---|
| 交互 shell | 看到 `>>` 后敲命令；`help` 列出内置提示，`exit` 退出（虚拟机停机）|
| 跑任意测试 app | 直接敲名字：`cat_filea`、`cmdline_args a b`、`forktest`、`pipe_large_test`、`mutex_test`、`sync_test`、`thread_test`、`sig_test`、`simd_test`、`fs_perf`、`03sbrk`、`filetest_simple`、`pipetest`、`00hello_world`、`01yield`、`02busy`、`conc_test` |
| 文件系统 | easy-fs，2MB RAM 盘；`hello.txt` 已存在；`filetest_simple` 演示创建/写/读/截断 |
| 进程/线程 | `fork` / `exec` / `waitpid`；`thread_create` / `gettid` / `waittid` |
| 同步原语 | mutex / semaphore / condvar |
| IPC | pipe / dup；信号（kill / sigaction / sigprocmask / sigreturn）|
| 内存 | `sbrk` 扩堆；块缓存（32 块 LRU）；停机打印页帧/内核堆/缓存统计 |
| 标准输入输出 | stdout 同时写 UART 和共享内存；stdin 来自共享内存（root 侧转发）|

### 4. ivshmem（共享内存 / ivshmem-net）

物理布局（两边同地址）：

| 区域 | 地址 | 大小 | 权限 |
|---|---|---|---|
| 状态表 | `0x6FFFE000` | 4KB | 只读（hypervisor 维护）|
| peer0 输出（root 的 TX → guest 的 RX）| `0x6FFFF000` | 0x7F000 | root 可写，guest 只读 |
| peer1 输出（guest 的 TX → root 的 RX）| `0x7007E000` | 0x7F000 | guest 可写，root 只读 |
| 寄存器（PCI BAR0）| `0xFFA00000` | 4KB | 读写 |

我们在每段上放了一个简单的字节环（见 `os-cell3/src/ivshmem.rs`）：

```
off 0  magic 'RCSH'   off 4  gen（代数）   off 8  write
off 12 read           off 16 cap            off 20 data[cap]
```

**两种驱动模式，二选一，不能同时用：**

| 模式 | 接口 | 用途 | 怎么切 |
|---|---|---|---|
| `ivshmem-net` | 网卡 `ivshm0`（10.0.0.1/24）| 给 Linux 对端做网络（virtio vring + 以太帧）| unbind uio + bind net |
| `uio_ivshmem` | `/dev/uio0`，可 mmap | 用户态直接读写共享内存（我们的控制台）| `scripts/setup-ivshm-uio.sh` |

uio 给出的 4 个映射（root 视角）：

| map | 内容 | 权限 |
|---|---|---|
| map0 | `0xFFA00000` 4KB 寄存器 | RW |
| map1 | `0x6FFFE000` 状态表 | RO |
| map2 | `0x6FFFF000` 起两段（两边的输出）| RO |
| map3 | `0x6FFFF000` 一段（root 自己的输出）| RW |

> `ivshmem-net` 模式只对“会说 virtio vring + 以太帧”的对端有意义；我们的 rc-aarch
> 没有实现网卡协议，所以 `ivshm0` 和它之间**不能传数据**（控制台走的是 uio 那条路）。

## 二、常用操作

### 2.1 编译 + 部署（日常）

```sh
cd ~/rc-aarch/os-cell3 && RUSTUP_TOOLKIT=stable cargo build --release
cd ~/rc-aarch
RELOAD=1 ROOTCELL=root@192.168.31.75 \
  SSHOPTS="-F /dev/null -o StrictHostKeyChecking=accept-new" \
  ./scripts/deploy-cell3.sh
```

- 板子刚重启（cell 还不存在）：去掉 `RELOAD=1`，走完整 create。
- 不要用 `cell destroy`（会把 CPU3 还给 Linux，可能触发 SError 掉板）。

### 2.2 交互 shell（最常用）

终端 2 先起控制台，终端 1 再部署：

```sh
# 终端 2
ssh root@192.168.31.75
/root/ivshm-console -i -d 600

# 终端 1
RELOAD=1 ROOTCELL=root@192.168.31.75 ./scripts/deploy-cell3.sh
```

回到终端 2，看到 `>>` 后敲：

```
help
cat_filea
cmdline_args hello world
forktest
exit
```

若顺序反了（先部署再起控制台），先清一下残留输入：`/root/ivshm-console -r`。

### 2.3 读控制台 / 日志

```sh
# 增量读（推荐，和部署脚本一致）
ssh root@192.168.31.75 'exec 3</dev/jailhouse; dd bs=8192 count=1 iflag=nonblock <&3'

# 快照（只有前 2KB）
ssh root@192.168.31.75 'cat /sys/devices/jailhouse/console'
```

宿主机验收产物：`verify-chapters.log`（控制台）、`verify-shell.log`（控制台会话）。
板端验收产物：`/root/verify-board.log`、`/root/verify-board-shell.log`。

### 2.4 板端本地验收（不依赖宿主机驱动）

```sh
# 宿主机：编译 + 上传（内核/cell/守护进程/板端脚本）
./scripts/pack-verify.sh

# 板子上：跑
ssh root@192.168.31.75
sh /root/verify-on-board.sh
```

### 2.5 只跑某一个测试

在交互 shell 里直接敲名字（等价于 `exec` 一个 app）：

```
pipe_large_test
mutex_test
fs_perf
sig_test
```

### 2.6 切换 ivshmem 模式

```sh
# net → uio（给控制台用）
ROOTCELL=root@192.168.31.75 ./scripts/setup-ivshm-uio.sh

# uio → net（给网络用）
ssh root@192.168.31.75 '
  echo -n 0001:00:00.0 > /sys/bus/pci/drivers/uio_ivshmem/unbind
  echo -n 0001:00:00.0 > /sys/bus/pci/drivers/ivshmem-net/bind
  systemctl restart ivshmem-net-up-host.service
'
```

### 2.7 板子重启后怎么恢复

| 症状 | 处理 |
|---|---|
| IP 变了 / ping 不通 | `MAC=dc:a6:32:cc:41:b4 ./scripts/find-board.sh`（MAC 从仓库移除了，要显式给）|
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | `ssh-keygen -R 192.168.31.75` |
| 免密失效（authorized_keys 丢）| `PUB=$(cat ~/.ssh/id_ed25519.pub); ~/.local/bin/rc-ssh root@192.168.31.75 "mkdir -p /root/.ssh && echo '$PUB' >> /root/.ssh/authorized_keys"` |
| `jailhouse` 命令报没使能 | `jailhouse enable /usr/share/jailhouse/cells/rpi4.cell` |
| 没有 `/dev/uio0` | 跑 `scripts/setup-ivshm-uio.sh` |
| 虚拟机文件丢了 | 重新 `./scripts/pack-verify.sh` / 重新部署（root cell 是内存文件系统）|

## 三、能力矩阵：想做什么 → 去哪层

| 我想…… | 在哪层 | 用什么 |
|---|---|---|
| 改内核/加系统调用 | 宿主机 | `os-cell3/src/`，改完 `cargo build` + 部署 |
| 加一个用户测试 app | 宿主机 | `user/src/bin/*.rs`，build 自动打包 |
| 跑全套验收 | 宿主机或板端 | `verify-chapters.sh` / `verify-on-board.sh` |
| 看虚拟机输出 | root cell | `/dev/jailhouse`（增量）|
| 和虚拟机交互 | root cell | `/root/ivshm-console -i` |
| 读写共享内存（自己做工具）| root cell | `/dev/uio0` 的 map2/map3 + 上面的环协议 |
| 让 root 和别的 Linux 分区组网 | root cell | `ivshm0`（ivshmem-net 模式）|
| 采集虚拟机日志/做转发 | root cell | `ivshm-console` 改造，或按环协议自己写 |
| 验证启动/调度/内存/文件/同步 | 虚拟机 shell | 直接跑对应 app |

## 四、边界与限制（重要）

1. **串口只有输出**：mini-UART 的 RX 被 root cell 的 Linux 占用，guest 没法从串口读输入；输入只能走共享内存。
2. **root cell 是内存文件系统**：`/root`、`/tmp` 重启即丢；每次重启都要重新上传/使能/放公钥。
3. **没有块设备**：guest 只有 2MB 的 easy-fs RAM 盘（内存里），没有 SD 卡/eMMC 可用。
4. **内存上限**：guest 约 30MB（`0xFA104000–0xFC000000`），内核堆 256KB；app 要小。
5. **ivshmem 两种模式互斥**：开了 uio 就没有 `ivshm0`，反之亦然；切换时别同时跑守护进程。
6. **`ivshm0` 和 rc-aarch 不能互通**：我们的 OS 没实现 virtio vring/以太帧。
7. **不要 `jailhouse cell destroy`**：有掉板风险；用 `shutdown → load → start`。
8. **时间**：guest 只有 `get_time()`（开机以来的毫秒），没有 RTC 墙钟。
9. **网络**：宿主机和板子之间的登录依赖 SSH；板端 `authorized_keys`、IP 都是易失的。

## 五、关键地址 / 编号速查

| 项 | 值 |
|---|---|
| 内核加载/链接地址 | `0xFA000000`（LOADABLE 区，也是 `cpu_reset_address`）|
| guest RAM | `0xFA100000` 起，约 31MB |
| 通信区（comm region）| `0xFC000000` |
| mini-UART | `0xFE215040` |
| GICD / GICC（guest 视角）| `0xFF841000` / `0xFF842000` |
| ivshmem 状态表 / 两段输出 | `0x6FFFE000` / `0x6FFFF000`、`0x7007E000` |
| ivshmem 寄存器（BAR0）| `0xFFA00000` |
| PCI 设备 | `0001:00:00.0`（`110a:4106`）|
| cell 名 / CPU | `rc-aarch` / CPU3（root 用 0–2）|
| RAM 盘 | 4096 块 × 512B = 2MB |
| 块缓存 | 32 块 LRU，写回 |
